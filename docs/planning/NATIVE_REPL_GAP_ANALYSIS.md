## 三、缺失的关键功能

### 3.1 高优先级缺失

1. **多行输入编辑**
   - 原版支持多行编辑、光标移动、选择
   - Native 仅支持单行输入

2. **权限确认交互**
   - 原版有完整的权限确认弹窗
   - Native 缺少交互式确认

3. **自动补全**
   - 原版 Tab 补全命令、文件路径、工具名
   - Native 完全缺失

4. **消息渲染**
   - 原版支持 Markdown、代码高亮、差异对比
   - Native 仅输出纯文本

### 3.2 中优先级缺失

1. **Token 预算管理**
   - 输入/输出 Token 计数
   - 预算警告和自动压缩

2. **会话管理**
   - 会话分叉 (/branch)
   - 多会话切换

3. **Agent 模式**
   - 自动执行模式
   - 后台任务管理

### 3.3 低优先级缺失

1. **Vim 模式**
2. **SSH 远程**
3. **IDE 集成**
4. **文件预览**

## 四、实现差距原因

### 4.1 架构差异

| 原版 | Native |
|------|--------|
| React + Ink 全屏 UI | 纯 Node.js readline |
| 组件化状态管理 | 简单类状态 |
| 事件驱动架构 | 同步流程 |
| 丰富的 UI 组件 | console.log |

### 4.2 依赖差异

原版依赖的关键库：
- `ink` - React 终端 UI
- `react` - 组件框架
- `@inkjs/ui` - UI 组件
- `figures` - Unicode 符号
- `ansi-escapes` - 终端控制

Native 仅依赖：
- `readline` - Node.js 内置

## 六、建议方案

### 方案 A：继续简化版（当前）

- 优点：轻量、无依赖、易于维护
- 缺点：功能不完整
- 适用：简单脚本、自动化任务

### 方案 B：Ink 集成版

- 优点：复用原版组件、功能完整
- 缺点：依赖增加、体积增大
- 适用：完整交互体验

### 方案 C：混合方案（推荐）

- 基础模式：简化版（当前）
- 完整模式：通过 `--ink` 参数启用 Ink UI
- 两套实现并存，按需选择

```bash
# 简化版（默认）
bun run packages/cli/src/entrypoints/native.ts

# 完整版（Ink UI）
bun run packages/cli/src/entrypoints/native.ts --ink
```
